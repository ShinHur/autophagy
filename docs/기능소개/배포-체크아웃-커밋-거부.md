# 릴리스 체크아웃의 커밋 거부

## 무엇을

배포용 체크아웃이 원격 기준의 단방향 미러로만 동작하도록, 그 안에서의 커밋을 구조적으로 거부하는 정책이다.

## 왜

운영 미러에서 만든 커밋은 다음 수렴에서 유실되거나 다른 배포를 막는다. 수정은 개발 작업본에서 검토돼야 한다.

## 사용 시나리오

운영자가 실수로 미러에서 커밋하려 하면 훅이 거부하고 안전한 복구 경로를 안내한다. 동기화에 필요한 fetch와 fast-forward 갱신은 허용된다. 앞선 변경이 발견되면 먼저 보존한 뒤 개발 브랜치에서 검토한다.

## 관련

`automation/bootstrap-accounts.sh`, `automation/checkout_mirror_probe.sh`
