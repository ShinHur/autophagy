# 산출물 Drive 아카이빙

이 기능은 추적 문서 산출물을 소유자 전용 Drive 폴더에 동기화합니다. 업로드는 외부효과이므로
언제나 해시 바인딩된 배치 승인 뒤에만 수행합니다.

## 범위

아카이브 대상은 계획·노트·기능 문서·마스킹된 QA·변경 기록처럼 추적 가능한 문서로
한정합니다. 소스코드, 시크릿, 런타임 상태, 비공개 경로는 대상에서 제외합니다. 대상 분류는
하나의 라우팅 테이블이 결정하며, 다이제스트와 업로더가 같은 테이블을 공유해야 합니다.

## 흐름

```text
변경분 열거 → 매니페스트(경로+해시) 생성 → 승인 다이제스트 게시
  → ✅ 승인 확인 → 현재 상태 재해시 → Drive upsert → 성공 receipt와 cursor 기록
```

- 변경이 없으면 어떤 메시지도 게시하지 않습니다.
- 다이제스트에는 소유자가 판단할 수 있는 파일 수·분류·대상 폴더·action hash를 표시합니다.
- 파일이 다이제스트 후 바뀌면 action hash가 달라지므로 업로드를 fail-closed로 거부합니다.
- 파일마다 성공 후 receipt를 기록해 중단 뒤 재개할 때 이미 올린 파일을 다시 처리하지 않습니다.

## 승인 메시지 단일성

프로젝트별 라이브 승인 메시지는 논리 요청마다 하나입니다.

1. producer와 watcher는 같은 lease를 사용합니다.
2. 같은 해시는 기존 메시지를 재사용하고, 다른 해시는 이전 메시지를 명시적으로 supersede한
   뒤에만 게시합니다.
3. 소유자가 이미 ✅ 또는 ⛔를 남긴 메시지는 producer가 삭제하지 않고 watcher에 양보합니다.
4. 메시지 생존·내용 바인딩·저장소 상태를 확인할 수 없으면 재게시하지 않습니다.

## 운영 경계

상태 디렉터리는 `DRIVE_ARCHIVE_STATE_DIR`로 지정하고 체크아웃 밖에 둡니다. 스케줄 작업은
리액션만 폴링하며, 자격증명이 필요한 자식 프로세스에는 명시적으로 환경을 전달합니다.
자세한 공통 규칙은 [Watcher-Cron 설계 규약](watcher-cron-설계규약.md)을 따릅니다.
