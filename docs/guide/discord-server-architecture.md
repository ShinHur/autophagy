# Discord 협업 서버 아키텍처

이 문서는 연구 협업용 공유 서버와 소유자별 개인 서버를 함께 쓰는 Discord 아키텍처의
규약입니다. 실제 서버 이름, 채널 식별자, 봇 사용자 식별자는 저장소에 기록하지 않고 환경
설정으로만 관리합니다.

## 아키텍처 요지

- **공유 서버**: 연구자 간 토론, 구조화된 상태 보고, 봇 간 조율을 위한 공용 공간입니다.
- **개인 서버**: 스킬 공급망 승인처럼 두 자동화 주체가 함께 확인해야 하는 작업을 위한
  격리 공간입니다.
- **소유자 전용 승인**: 메일, 일정, 예산처럼 개인 데이터를 포함할 수 있는 외부효과는
  행위 봇과 소유자 사이의 DM에서만 처리합니다.

```text
[공유 서버]                         [개인 서버]
  #team       사람 중심 대화            #approvals  공급망 승인
  #agents-log 구조화된 상태 보고
  #agent-coordination 봇 간 봉투
```

## 채널 계약

| 서버 | 채널 | 용도 |
|---|---|---|
| 공유 | `#team` | 사람과 봇의 일반 논의 |
| 공유 | `#agents-log` | 마스킹된 구조화 작업 보고 |
| 공유 | `#agent-coordination` | 봇 간 조율 봉투 |
| 개인 | `#approvals` | 스킬 배포·발행·활성화의 공급망 승인 |

공유 서버에 `#approvals`를 추가하지 않습니다. 채널 이름 기반 탐색을 쓰는 구현에서는 각
봇의 시야에 개인 서버의 승인 채널만 하나가 되도록 유지하고, 둘 이상을 확인하면
fail-closed로 중단해야 합니다.

## 식별자와 멤버십

- 봇·서버의 표시 이름은 사람이 읽기 위한 라벨일 뿐, 권한 판단에는 사용자 ID를 사용합니다.
- 실제 식별자는 `.env.example`의 `DISCORD_GUILD_ID`, `DISCORD_APPROVALS_CHANNEL_ID`,
  `DISCORD_OWNER_DM_CHANNEL_ID`, `DISCORD_OWNER_ID` 같은 비공개 환경 변수에 둘니다.
- 각 봇은 필요한 서버에만 참여하고, 허브 수집 봇에는 읽기 전용 권한만 부여합니다.
- 개인 서버 이름에 실명·생일·조직 정보를 넣어야 한다면 저장소와 공개 로그에는
  `<PERSONAL_SERVER_NAME>`만 씁니다.

## 승인 표면 규칙

1. 공급망 승인은 개인 서버 `#approvals`에서 처리합니다. 두 번째 검증 봇도 이 채널을
   볼 수 있어야 합니다.
2. 소유자 전용 승인에는 DM을 사용합니다. 개인 서버 채널로 대체해 가시 범위를 넓히지
   않습니다.
3. 승인 레코드에는 게시 시 확정한 채널 식별자를 바인딩합니다. 이후 조회·리액션·삭제는
   이 저장값만 사용합니다.
4. 같은 논리 요청에는 승인 메시지를 하나만 유지하며, 이미 결정된 메시지는 생산자가
   삭제하거나 교체하지 않습니다.

## 설정과 온보딩

서버를 만들 때는 먼저 채널 계약과 최소 권한을 합의하고, 봇 초대 뒤 실제 ID를 비공개
설정에 넣습니다. 구조화 보고와 조율 봉투의 형식은 [인터롭 규약](interop-규약.md)을,
참여자별 설치 순서는 [온보딩 킷](onboarding-kit.md)을 따릅니다.
