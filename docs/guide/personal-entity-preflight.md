# 개인 고유명사 Preflight 계약

외부 시스템에 쓰기 전에 사용자 문장의 개인 고유명사를 해석하고, 단일 고신뢰 후보일 때만
정규화 값을 draft에 넣는 계약입니다. 이 단계는 외부효과 승인 게이트를 대체하지 않습니다.

## 흐름

1. 호출자가 입력·대상 시스템·작업을 담은 `PreflightInput`을 만듭니다.
2. 결정론적 파서가 `DetectedEntity`와 필요한 `RelationshipQuery`를 만듭니다.
3. 개인 RAG, 메모리, 주소록 같은 read-only `CandidateResolver`가 후보를 반환합니다.
4. 정책이 단일 고신뢰 후보를 고르면 정규화 값을 최종 draft에 넣습니다.
5. 충돌·저신뢰·후보 없음이면 `ENTITY-CLARIFY`를 출력하고 쓰기와 승인 메시지 생성을 모두
   중단합니다.
6. 기존 승인 게이트가 최종 payload를 승인한 뒤에만 write adapter가 실행됩니다.
7. write 성공 뒤 API 재조회가 일치할 때만 `VERIFIED`로 기록합니다.

## 정책

정책은 추적되는 불변 시드 한 곳에 두고, 파일 누락·형식 오류·가중치 누락은 fail-closed로
처리합니다. 대표값은 자동선택 하한, 충돌 하한, 1·2위 점수 차이입니다. 여러 entity 중 하나라도
확정할 수 없으면 전체 요청을 clarify로 돌립니다.

## 개인정보 경계

원문, 표면형, 관계 질의, 후보의 표시·정규화 값, 출처 참조는 private 감사 저장소에만
보관합니다. 일반 운영 로그에는 불투명 correlation ID, 대상 시스템, entity 수, 후보 수,
결정 enum, 지연 시간처럼 개인정보 없는 지표만 기록합니다.

품질 지표는 자동 정규화율, clarify율, 검증 실패율, p95 지연, guard bypass 수를 집계할 수
있지만, 지표 집계가 새 외부 전송이나 승인 표면을 만들면 안 됩니다.
