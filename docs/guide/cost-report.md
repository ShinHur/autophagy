# 일일 LLM 비용 리포트 운영 가이드

일일 지출을 소유자에게 요약해 알리는 배치 작업의 일반 설계입니다. 이 작업은 LLM 호출이
필요 없는 데이터 처리로 구현하고, 원시 사용량·자격증명·요청 본문은 리포트 경로에 넣지
않습니다.

## 목표와 경계

- 비용 데이터가 있는 계층만 원시 사용량 저장소에 접근한다.
- 발송 계층은 기간별 합계·예산 경보·마스킹된 키 별칭만 받는다.
- 리포트 전송은 개인 메시지 또는 동등한 소유자 전용 표면으로 제한한다.
- 스케줄러 실패는 관측하되, 실패를 숨기기 위해 중복 리포트를 재발송하지 않는다.

## 권장 구조

```text
[비용 저장소 접근 계층]
  원시 사용량 조회 → 허용 필드 집계 → 마스킹된 JSON 한 줄
                                      │
                                      ▼
[리포트 작업]
  집계 검증 → 기간/예산 문구 생성 → 2차 레닥션 → 소유자 전용 전송
```

두 계층을 분리할 때는 리포트 작업에 데이터베이스 URL·관리자 키·원시 로그 읽기 권한을
부여하지 않습니다. 필요한 경우 제한된 명령 또는 읽기 전용 API가 집계만 반환하도록 합니다.

## 구현 규칙

1. 원시 이벤트는 접근이 제한된 런타임 저장소에만 기록합니다. 스냅샷 파일 위치는
   `COST_REPORT_SNAPSHOT_FILE`로 정합니다.
2. 전송 전에 토큰·인증 헤더·전자우편 주소·플랫폼 식별자·긴 숫자 식별자를 다시 마스킹합니다.
3. 집계 입력이 비어 있거나 형식이 맞지 않으면 발송하지 않고 실패로 끝냅니다.
4. 경보 임계값은 `COST_REPORT_SOFT_CAP` 같은 설정값으로 두고, 통화와 기간을 본문에 함께
   표시합니다.
5. 미리보기는 `COST_REPORT_DRY_RUN=1`에서만 허용하며, 이 모드에서는 네트워크 전송을 하지
   않습니다.

## 스케줄과 검증

스케줄러에는 작업 이름·시간대·실행 계정·성공/실패 관측 방식을 명시합니다. 실행 전에는
다음을 확인합니다.

- 비용 조회 명령이 집계만 반환하는가
- 미리보기 출력에 민감값이 없는가
- 전송 대상이 소유자 전용 표면인가
- 실패 시 비정상 종료 코드와 원인 분류가 남는가

새 스케줄 작업은 [Watcher-Cron 설계 규약](watcher-cron-설계규약.md)의 환경 전파·상태 마킹
규칙을 따라야 합니다.
