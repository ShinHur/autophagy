# 팀 에이전트 보고 허브 운영 가이드

보고 허브는 공유 `#agents-log`의 구조화된 인터롭 리포트를 읽어 접근 제한된 저장소에
적재하고, 인증된 대시보드로 집계 상태만 보여줍니다.

## 구성

| 구성요소 | 책임 |
|---|---|
| 콜렉터 | 채널을 읽고 규약 리포트를 엄격히 파싱·분류 |
| 저장소 | 정상 리포트와 격리 리포트를 분리해 upsert |
| 대시보드 | 등록 상태와 집계만 인증된 사용자에게 표시 |
| 등록부 | `agent_id`와 봇 사용자 ID의 대응을 검증 |

원시 메시지·채널 식별자·인증 정보는 체크아웃 밖의 비공개 런타임 저장소에만 둡니다 —
수집기의 DB 경로는 `REPORT_HUB_DB`(필수, 기본값 없음), 격리 로그는
`REPORT_HUB_QUARANTINE_LOG`로 지정합니다. 대시보드의 바인드 주소와 자격증명도 배포
환경의 변수로만 설정합니다.

## 처리 규칙

1. 파서는 [인터롭 규약](interop-규약.md)의 버전·필드 집합·상태 enum을 모두 확인합니다.
2. 형식 오류, 등록부 불일치, 위조된 작성자 정보는 격리 저장소로 보내고 주 테이블에는
   적재하지 않습니다.
3. 콜렉터는 메시지 식별자를 키로 upsert하여 재시작 후 backfill이 일어나도 중복 행을 만들지
   않습니다.
4. 새 참여자를 등록해도 과거 리포트를 삭제하지 않습니다. 다음 수집 시 등록 상태만 재분류합니다.
5. 대시보드는 비공개 네트워크에 바인딩하고 인증 설정이 없으면 기동을 거부합니다.

## 운영 절차

- **참여자 등록**: 등록부 변경을 검토·배포한 뒤 콜렉터가 새 설정을 읽도록 조건부 재시작합니다.
- **수집 지연**: 콜렉터 상태와 워터마크를 먼저 확인하고, 정상 복구 뒤 자동 backfill을
  기다립니다. 보고를 수동으로 재게시하지 않습니다.
- **대시보드 인증 변경**: 전용 회전 도구가 있는 경우에만 사용하고, 새 자격증명으로 실제
  로그인 검증에 성공한 뒤에만 이전 값을 폐기합니다.

헬스체크는 콜렉터·대시보드 상태와 인증 없는 요청의 거부 여부만 확인해야 하며, 메시지
본문이나 인증값을 로그에 기록해서는 안 됩니다.
