# Discord 서버와 봇 설정 가이드

이 문서는 협업 에이전트용 Discord 서버와 봇을 만들 때의 일반 절차입니다. Portal 화면은
변할 수 있으므로 화면의 이름보다 권한 목적과 검증 기준을 우선합니다. 토큰 생성·서버 초대·
실제 권한 변경은 소유자가 수행합니다.

## 1. 서버와 채널 만들기

공유 협업 서버와 소유자별 개인 서버를 분리합니다. 채널 구성과 승인 경계는
[Discord 협업 서버 아키텍처](discord-server-architecture.md)가 정한 계약을 사용합니다.

- 공유 서버: `#team`, `#agents-log`, `#agent-coordination`
- 개인 서버: `#approvals`

실제 서버·채널 ID는 `.env.example`의 `DISCORD_GUILD_ID`, `DISCORD_APPROVALS_CHANNEL_ID`,
`DISCORD_OWNER_DM_CHANNEL_ID`에 비공개로 채우고, 추적 파일에는 쓰지 않습니다. 서버
이름에 개인 식별 정보가 포함되면 문서·로그에는 `<PERSONAL_SERVER_NAME>`만 기록합니다.

## 2. 봇 애플리케이션 만들기

각 역할에는 별도 애플리케이션과 별도 토큰을 사용합니다. 예를 들면 대화 봇, 검증 봇,
읽기 전용 수집 봇을 분리할 수 있습니다.

1. Developer Portal에서 애플리케이션을 만들고 Bot 기능을 추가합니다.
2. 필요한 메시지 내용을 읽어야 한다면 **Message Content Intent**를 켭니다.
3. 토큰은 한 번만 복사해 mode `0600`의 비공개 시크릿 파일 또는 전용 비밀 저장소에 넣습니다.
4. 토큰 노출이 의심되면 해당 봇의 토큰만 회전하고, 다른 봇의 토큰을 재사용하지 않습니다.

토큰·인증 헤더·사용자 ID를 명령행, 셸 이력, QA 증적, 스크린샷에 넣지 않습니다.

## 3. 최소 권한으로 초대

| 봇 역할 | 권한 원칙 |
|---|---|
| 대화·승인 봇 | 채널 보기, 메시지 전송, 기록 읽기, 필요한 리액션·스레드 기능 |
| 검증 봇 | 대화 봇과 분리된 자격증명, 필요한 채널에만 최소 권한 |
| 수집 봇 | 채널 보기와 기록 읽기만; 쓰기 권한 없음 |

`Administrator`, 역할 관리, 서버 관리 권한은 부여하지 않습니다. 권한 변경 후에는 각 봇이
필요한 채널만 보이는지 확인합니다.

## 4. 검증

1. 각 봇의 자격증명이 값 노출 없이 유효한지 확인합니다.
2. 필요한 채널이 존재하고 역할별 접근이 최소 권한인지 확인합니다.
3. Intent를 바꿨다면 봇 프로세스를 재연결한 뒤 메시지 본문 수신을 확인합니다.
4. 소유자 전용 외부효과가 DM에서, 공급망 승인이 개인 서버 `#approvals`에서만 대기하는지
   확인합니다.

검증 증적에는 성공/실패 판정과 설정 항목 이름만 남기고, 토큰·실제 ID·원시 API 응답은
포함하지 않습니다.
