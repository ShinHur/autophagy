# Google Workspace CLI OAuth 설정 가이드

이 문서는 Google Workspace 호환 CLI를 개인 자동화에 연결할 때의 최소 권한 OAuth 절차입니다.
CLI 버전과 명령 문법은 변할 수 있으므로 실행 전 해당 버전의 공식 도움말을 확인합니다.

## 원칙

- OAuth 클라이언트와 사용자 자격증명은 비공개 저장소에만 둡니다.
- 필요한 서비스와 동작에 맞는 최소 scope만 요청합니다.
- 사람이 브라우저에서 로그인·동의하고, 헤드리스 실행 환경에서는 브라우저 로그인을 시도하지
  않습니다.
- 자격증명 파일·암호화 키·원시 API 응답을 저장소, 메시지, 증적에 넣지 않습니다.

## 범위 설계

필요한 서비스별로 scope를 선택합니다. 예시는 Calendar, Drive, Sheets, Gmail 전송, Tasks입니다.
읽기 전용 기능에 쓰기 scope를 추가하거나, 사용하지 않는 서비스의 scope를 미리 요청하지
않습니다. scope 변경 뒤에는 새 동의가 필요할 수 있음을 운영 절차에 명시합니다.

## 설정 절차

1. 소유자 워크스테이션에서 OAuth client 설정을 확인하고 새 로그인 흐름을 시작합니다.
2. 동의 화면에서 설계한 scope만 허용합니다.
3. 인증 상태가 유효한지 화면에서 확인하되, 계정 주소·토큰·전체 status 출력은 기록하지
   않습니다.
4. 자동화 실행 계정에 자격증명이 필요하면 운영 비밀 저장소 또는 일회성 보호 전송 경로를
   사용합니다. 전송 뒤에는 staging 사본을 삭제하고 소유권과 mode `0700`/`0600`만 확인합니다.
5. CLI 경로와 실행 계정을 고정하고, 크론에서는 필요한 `PATH`와 자격증명 위치를 명시합니다.

## 안전한 검증

먼저 읽기 전용 호출로 연결을 확인합니다. Drive 업로드, Sheets 갱신, Calendar 변경, Gmail
전송처럼 외부효과가 있는 검증은 기존 승인 게이트를 거친 별도 작업으로만 수행합니다.
증적은 `PASS` 또는 `FAIL`과 기능명만 포함해야 합니다.

외부효과를 호출하는 워처는 [Watcher-Cron 설계 규약](watcher-cron-설계규약.md)의 자격증명
전파와 승인 메시지 단일성 규칙을 따라야 합니다.
