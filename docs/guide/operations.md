# 운영 가이드

이 문서는 여러 계정·노드에 나뉜 에이전트 시스템의 안전한 일상 운영 원칙입니다. 실제
호스트명, 주소, 계정명, 포트, 비공개 경로는 배포 설정과 운영 비밀 저장소에서 관리합니다.

## 기본 원칙

- 상태 확인이 먼저이며, 정상 서비스는 확인 목적으로 재시작하지 않습니다.
- 원인을 확인하기 전 설정·키·네트워크 규칙을 바꾸지 않습니다.
- 외부효과는 기존 소유자 승인 게이트를 우회하지 않습니다.
- 런타임 상태와 시크릿은 체크아웃 밖의 접근 제한 저장소에만 기록합니다.

## user-systemd 명령 형태

원격 사용자 unit은 실행 계정의 user bus를 명시해 호출합니다.

```bash
ssh <NODE> "sudo -n -u <ACCOUNT> env XDG_RUNTIME_DIR=/run/user/\$(id -u <ACCOUNT>) \
  systemctl --user <VERB> <UNIT>"
```

`is-active`와 `status`로 진단하고, 실패 원인이 확인된 unit만 `restart`합니다. unit 파일을
바꾼 경우에만 `daemon-reload`를 실행합니다.

## 일일 점검 순서

1. LLM 게이트웨이, 에이전트 gateway, 검색 서비스, 보고 허브 등 의존 순서가 있는
   구성요소를 상태 확인합니다.
2. 읽기 전용 healthcheck를 실행해 서비스별 실패를 분류합니다.
3. 스케줄러 목록에서 작업의 다음 실행과 마지막 결과를 확인합니다.
4. 실패한 구성요소의 제한된 로그만 확인하고, 원시 본문·자격증명은 복사하지 않습니다.

두 개 이상의 상호의존 gateway가 함께 동작하는 설계라면, 재시작이 필요할 때에도 항상
그 집합 전체를 같은 복구 창에서 재시작합니다. 단일 구성요소만 재시작해 상태가 불일치하는
것을 피하기 위함입니다.

## 대시보드와 자격증명

- 대시보드는 loopback 또는 사설 네트워크 인터페이스에만 바인딩합니다.
- 비-loopback 바인딩에는 인증을 강제하고, 인증 설정 누락은 기동 실패로 처리합니다.
- 자격증명은 전용 회전 도구로만 교체합니다. 평문은 표준출력·명령행·로그·증적에 남기지
  않습니다.
- 회전 뒤에는 새 자격증명으로 로그인 검증을 하고, 실패 시 이전의 검증된 상태로 복구합니다.

## 배포·복구 경계

배포 체크아웃은 배포 기준 브랜치의 읽기 전용 거울로 취급합니다. 수정은 개발 체크아웃에서
검토·반영하고, 배포 환경은 허용된 동기화 절차로만 갱신합니다. 재부팅 이후에는
[재부팅 복구 절차](reboot-recovery.md)를, 증상별 판단에는
[장애 대응 트리](incident-response.md)를 사용합니다.
