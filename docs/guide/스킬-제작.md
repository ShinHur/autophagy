# 스킬 제작·배포 가이드

이 문서는 에이전트 스킬을 작성하고, 샌드박스·리뷰·소유자 승인·마운트로 이루어진 배포
절차를 통과시키는 방법을 설명합니다.

## 스킬 형식

```text
skills/<skill-name>/
├── SKILL.md
└── scripts/
    └── scenario.sh
```

`SKILL.md`에는 디렉터리명과 일치하는 `name`, 충분한 `description`, 버전 등 필요한
frontmatter를 둡니다. `scenario.sh`는 격리 환경에서 성공 시 `SCENARIO-PASS`를 출력하고
종료 코드 0으로 끝나야 합니다.

시나리오에는 실제 시크릿을 주입하지 않습니다. 시크릿 형태의 값·인증 헤더·개인키는 코드,
주석, 문서, 테스트 출력 어디에도 넣지 않습니다.

## 배포 흐름

1. **샌드박스**: 대상 런타임의 구문·의존성·디스커버리·시나리오를 격리 환경에서 검증합니다.
2. **리뷰와 승인 요청**: 콘텐츠 해시를 계산해 개인 서버의 공급망 승인 표면에 요청을 게시합니다.
3. **검증**: 소유자 승인과 필요한 두 번째 검증이 모두 유효한지 확인합니다.
4. **마운트**: 승인된 바이트를 복사하고 디스커버리·스모크 검증을 실행합니다.

샌드박스가 실패하면 승인 요청을 만들지 않습니다. 스킬의 내용이 바뀌면 이전 콘텐츠 해시는
재사용하지 않습니다.

## 승인 메시지 규칙

- 같은 콘텐츠 해시의 요청은 기존 라이브 메시지를 재사용합니다.
- 다른 콘텐츠는 기존 메시지를 안전하게 supersede한 뒤에만 새 요청을 만듭니다.
- 소유자가 이미 결정했거나 메시지·바인딩·저장소를 확인할 수 없으면 기존 메시지를 건드리지
  않고 fail-closed로 끝냅니다.
- 테스트 주입 승인은 격리된 회귀에만 허용하며, production gateway는 테스트 환경을 거부합니다.

## 관리형 스킬

관리형 스킬은 `managed-` 접두사를 사용하고, 일반 스킬과 이름 충돌 시 양방향으로 차단합니다.
발행·구독·활성화에는 [관리형 스킬 채널 가이드](managed-skill-channel.md)의 서명·격리·명시적
활성화 절차를 적용합니다.
