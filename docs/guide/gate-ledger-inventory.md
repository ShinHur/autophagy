# 승인 원장 인벤토리

이 문서는 승인 원장의 공개 가능한 스키마와 접근 경계를 설명합니다. 실제 원장 경로, 수량,
메시지 식별자, 원문 payload는 비공개 런타임 저장소에만 존재합니다.

## 공통 레코드

| 필드 | 설명 |
|---|---|
| `action` | 승인 대상 동작의 분류 |
| `approval` | 채널 참조, 메시지 참조, 승인 방식 |
| `hash` | 승인 대상의 정규화된 해시 |
| `result` | 승인·취소·실행 결과 상태 |
| `target_id` | 대상의 불투명 식별자 |
| `timestamp` | 처리 시각 |

스킬 배포, 일정, 메일, 문서 저장, 수리처럼 서로 다른 스트림은 같은 형식을 쓸 수 있지만,
민감도와 접근 권한은 분리합니다. 고민감 원장은 일반 수집 계정이 읽지 못하게 하고, 분석이
필요하면 마스킹된 파생 레코드만 제공합니다.

## 분석 원칙

- 스키마 키와 집계 수치만 공개 분석 대상으로 삼습니다.
- 메시지 본문, 대상값, 토큰, 개인 식별자, 원시 경로는 분석 레코드에 넣지 않습니다.
- 읽을 수 없는 원장은 건너뛰지 않고 접근 경계로 명시합니다.
- 새 스트림을 추가할 때는 원장 작성자, 보존 기간, 열람 주체, 레닥션 정책을 함께 검토합니다.
