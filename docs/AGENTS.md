# docs/ — 공개 지식 베이스

이 디렉터리는 공개 가능한 설계, 기능 인벤토리, 사용 중심 기능 소개를 담는다. 설치별 운영 기록·시점 의존 계획·원시 검증 로그는 포함하지 않는다.

## 분류

| 위치 | 내용 | 작성 원칙 |
|---|---|---|
| `design/` | 공개 설계와 경계 계약 | 공급자·환경 독립적인 규범과 제약을 설명한다. |
| `기능소개/` | 완료 기능의 짧은 소개 | 무엇·왜·합성 사용 시나리오·관련 공개 경로를 포함한다. |
| `features.md` | 공개 기능 인벤토리 | 포함 범위와 의도적 제외 범위만 기록한다. |
| `spark-활용-검토.md` | 일반 하드웨어 활용 판단 | 설치별 호스트·주소·포트·자격증명은 기록하지 않는다. |
| `설치-운영-매뉴얼.md` | 빈 머신에서 배포까지의 실행 순서 | 명령·플래그·성공 문자열은 트리의 코드와 대조해 적고, 저장소가 답하지 않는 공백은 숨기지 않는다. |

## 규칙

- 실제 수신자, 메시지 원문, 자격증명, 호스트, 주소, 계정, 운영 경로, 식별자는 문서에 넣지 않는다.
- 기능을 추가·변경·제거하면 설계·기능 소개·기능 인벤토리와 루트 `AGENTS.md`를 함께 갱신한다.
- 기능 소개의 사용 시나리오는 합성된 예시를 사용하고, 외부효과가 있으면 승인과 거부 경로를 설명한다.
- 내부 계획·티켓·세션·검증 증적은 공개 문서의 근거나 링크 대상이 아니다.
