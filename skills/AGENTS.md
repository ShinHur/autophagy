# skills/ — 에이전트 스킬 규약

스킬 하나는 `skills/<name>/` 디렉터리 하나다. 각 스킬은 사용 설명, 실행 진입점, 격리 시나리오, 필요 시 승인 워처와 배포 훅을 제공한다.

## 기본 형식

```
skills/<name>/
├── SKILL.md
├── scripts/
│   ├── <name>_cli.py
│   ├── scenario.sh
│   └── *watch.py
├── prompts/  configs/
└── deploy.sh
```

## 메타데이터와 시나리오

- `SKILL.md`의 `name`은 디렉터리명과 일치하고, `description`은 트리거·읽기·변경 경계를 설명한다.
- `version`, `license`, 태그는 권장한다.
- `scenario.sh`는 빈 환경과 더미 비밀에서 실행하며, 성공 시 `SCENARIO-PASS`와 종료 코드 0을 반환한다.
- 실제 비밀, 수신자, 운영 경로, 설치별 식별자를 시나리오와 문서에 넣지 않는다.

## 필수 안전 규칙

- 변경 경로는 반드시 공용 승인 게이트를 거친다. 새 승인 표면은 저장 레코드의 바인딩으로만 구분하고 별도 워처를 만들지 않는다.
- 겹치는 도메인은 양방향 결정론적 라우팅 가드를 구현한다. 자연어 설명만으로 두 경로의 동시 실행을 막을 수 없다.
- 워처 배포 파일명은 런타임에서 스킬별로 고유해야 한다.
- 런타임 상태는 `$AUTOPHAGY_RUNTIME_ROOT`에 보관하며, 추적 시드나 체크아웃 경로를 가리키면 fail-closed로 거부한다.
- 승인 메시지를 게시하는 스킬은 공용 approval lifecycle을 사용해야 한다. 불러오기에 실패했을 때 무가드 게시로 폴백하지 않는다.
